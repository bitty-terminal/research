# Bitty terminal core pipeline code review: bitty-vt / bitty-term-state / bitty-render

- **Scope**: `bitty/crates/bitty-vt` (VT parser: byte stream → `TerminalAction`), `bitty/crates/bitty-term-state` (terminal state machine: grid / cursor / modes / scrollback / damage / replies), `bitty/crates/bitty-render` (rendering: damage frame planning → `DrawList` → batching / atlas / GPU and software compositing).
- **File scale** (source + tests, counted via `rg --files`): bitty-vt 10 rs files (`src` 8: `action.rs`, `bounded.rs`, `kitty_apc.rs`, `lib.rs`, `parser.rs`, `parser/dispatch.rs`, `parser/sgr.rs`, `parser/tests.rs`; `tests` 2), bitty-term-state 23 rs files (`src` 17, `tests` 6), bitty-render 22 rs files (`src` 17 including `grid/tests.rs`, `tests` 5).
- **Method**: Read-only. First read the three crates' `Cargo.toml` and `lib.rs` (confirming the ADR-0003 dependency topology and the `forbid/deny(unsafe_code)` policy), then expanded key modules with `ctxctl outline` — `parser.rs`, `action.rs`, `state.rs`, `grid.rs` (one each in two crates), `batch.rs`, `frame.rs`, `cache.rs`, `atlas.rs`, `glyph.rs` — and read them section by section; used `rg` to trace `clone`/`to_vec` hotspots, `eprintln`, `expect`, `evict`, and damage/commit paths; spot-checked the parser state machine (including APC pre-scan and `held_esc` cross-packet logic), SGR/mode/OSC dispatch, Kitty APC reassembly, wide and zero-width characters, scrollback, damage merging, atlas/glyph cache, batch vertex serialization, the `present` commit loop, and the software compositing path. Every finding cites a repo-relative path and symbol name as evidence; no source code was modified.

## Defect list

### P0 (correctness: paints the wrong screen or drops damage, must fix)

- **D01 — `damage_since` window overflow has no full fallback; large cross-frame output causes under-damage (missed paint)**
  - Location: `bitty/crates/bitty-term-state/src/state.rs` (`State::apply` → `finalize_batch` pushes one history batch per action; `State::damage_since` directly concatenates retained batches).
  - Symptom: `DAMAGE_HISTORY_BATCHES = 64` (see `bitty/crates/bitty-term-state/src/damage.rs`), but history advances at action granularity, so one slightly large output (a few hundred `Print`s) fills all 64 batches between two frames. `damage_since(old)` only returns the batches still retained, with no "window exceeded → full repaint" fallback for genuinely evicted damage; when the render side does a partial repaint from the returned region set, the result is under-damage (missed paint).
  - Trigger: Any pair of frames with more than 64 actions between them (including inert `Unknown`/`OscClipboard`/`KittyGraphics` empty batches, which likewise occupy history slots), e.g. `cat` of a large file or a long `ls` listing before rendering catches up once.
  - Evidence: `finalize_batch` unconditionally `push_back`s (even an empty region occupies a slot); the `damage_since` comment only says "older than the retained window behave as a full-grid redraw request", but the implementation never returns a full grid, while the existing proptest (`damage_since_reconstructs_the_full_stream` in `bitty/crates/bitty-term-state/tests/replay_determinism.rs`) uses `prop_assert!(actions.len() < DAMAGE_HISTORY_BATCHES)` to actively constrain cases to inside the window, i.e. it excludes the overflow case from testing.

- **D02 — Whole-atlas eviction inside a frame invalidates slots of glyphs already emitted in the same frame, painting blank/wrong glyphs**
  - Location: `bitty/crates/bitty-render/src/grid.rs` (`GlyphAtlas::ensure` → `evict_all`; `GridRenderer::render` calls `ensure` in a loop and writes the returned `AtlasSlot` into `DrawList.glyphs`).
  - Symptom: `evict_all` performs `layout.reset()` + `slots.clear()` + `texels.fill(0)` + `pending.clear()`. If the number of distinct glyphs in one frame exceeds the atlas capacity (full-screen CJK, or a small atlas), the `uv`/`slot` of glyphs written earlier in the same frame into the `DrawList` point at zeroed texels, while the backend actually uploads only the `pending` data of the post-eviction layout, so the earlier glyphs sample an all-zero overlay → silent glyph loss, with no error on CPU or GPU.
  - Trigger: Distinct `RasterKey` count within one frame exceeds the current atlas capacity; a 200×62 full-screen CJK frame may already hit this under the default atlas, let alone the tiny 8×8 atlas shapes used in tests.
  - Evidence: The existing test `atlas_eviction_is_wholesale_and_deterministic` (`bitty/crates/bitty-render/src/grid/tests.rs`) asserts "only 'c' remains after eviction" and byte-identical output across two runs, but only verifies determinism and never verifies whether the `uv` of earlier glyphs in the same frame ('a', 'b') is still valid after eviction — exactly the observation window of this defect.

### P1 (correctness or performance: high hit probability / large cost)

- **D03 — `erase_range_in_row` uses `if-else` for two-sided wide-pair expansion, so it expands only one side when spanning two wide pairs at once**
  - Location: `bitty/crates/bitty-term-state/src/grid.rs` (the `start`/`end` adjustment at the top of `Grid::erase_range_in_row`).
  - Symptom: When the left end of the range lands on a spacer and the right end lands on a wide-char lead, the `else if` skips right-end expansion, leaving the spacer paired with the right end orphaned (a later `repair_row` fallback erases it, but the damage mark only covers the original range, so both the expansion semantics and the damage are imprecise).
  - Trigger: Erasing middle columns of a row such as `[wide][wide]` (left edge on a spacer, right edge on a lead). The two existing single-sided tests (`erase_range_expands_over_wide_pairs`, `erase_range_extends_into_trailing_half`) each cover only one side.
  - Evidence: The source `if start > 0 && ... { start -= 1; } else if ... { end += 1; }` should be two independent `if`s.

- **D04 — `Grid::resize` clears all soft-wrap flags on a height-only resize**
  - Location: `bitty/crates/bitty-term-state/src/grid.rs` (tail of `Grid::resize`: `self.wraps = vec![false; new_rows]`).
  - Symptom: When the width is unchanged and only the height changes, the `wraps` continuation relations of surviving rows should be preserved, but they are all reset to false; any later width reflow then unwraps former soft wraps as hard breaks, splitting logical lines and breaking cursor logical mapping and search positioning with it.
  - Trigger: Produce `wraps=true` rows via auto-wrap, then do one equal-width height change (e.g. dragging a split height), then change the width.
  - Evidence: The height-only branch comment in `State::resize` only says "truncate/pad both grids" with no mention of wraps preservation; `Grid::resize` unconditionally rebuilds an all-false vector.

- **D05 — `State::snapshot` clones the whole grid, and `search` takes one snapshot per call**
  - Location: `bitty/crates/bitty-term-state/src/state.rs` (`State::snapshot` → `flatten_cells` clones the full `Box<[Cell]>`); `bitty/crates/bitty-term-state/src/search.rs` (`State::search` contains `let snap = self.snapshot()`).
  - Symptom: The grid cap is `MAX_GRID_DIM = 1000`, so a single snapshot of a 1000×1000 grid clones about a million `Cell`s (each containing a `Style` + `Vec<char>` header + hyperlink), tens of MB; rendering once per frame and searching once per call makes the cost grow linearly with grid area.
  - Trigger: Per-frame rendering and search under a large grid (200×62 is already 12400 cells; the limit configuration is 1M cells).
  - Evidence: `search` only needs a row view of the live grid but takes the full `snapshot()` path; `render` likewise clones the full grid every frame.

- **D06 — Single-packet/unknown-format Kitty decode payload is only bound by the 320MB ledger; the `s/v` claim check can be bypassed**
  - Location: `bitty/crates/bitty-vt/src/kitty_apc.rs` (`feed_new` single-packet path; `validate_raw_claim` only checks when `f=24/32` with both `s`/`v` present and nonzero).
  - Symptom: `f=100` (PNG) ignores `s/v` entirely, and unknown `f` skips the claim check; after decoding, the only comparison is against `ledger_cap` (320MB). An attacker can use a huge base64 payload (e.g. a 200MB PNG/unknown-format payload) to make the parser first allocate a huge `Box<[u8]>` and then hand it to the runtime, which fails to decode — a memory spike far above the `KITTY_APC_DECODE_MAX_BYTES` (64MB) design intent.
  - Trigger: A single-packet APC of the form `Gf=<non-24/32>,m=0;<huge valid base64>`.
  - Evidence: The single-packet path's `decoded.len() > self.ledger_cap` check is followed by no threshold related to `KITTY_APC_DECODE_MAX_BYTES`.

- **D07 — Reject path uses `eprintln!`; a malicious APC stream can flood logs and slow the PTY hot path**
  - Location: `bitty/crates/bitty-vt/src/parser.rs` (`eprintln!` when over the ledger); `bitty/crates/bitty-vt/src/kitty_apc.rs` (`warn_reject` prints on every `Rejected(non-NotGraphics)`).
  - Symptom: Every rejection blocks on writing stderr; a sustained malformed-APC stream both amplifies PTY processing latency and can fill logs. Diagnostics should go to telemetry counters/sampled logs, not unconditional `eprintln!`.
  - Trigger: The peer (plugin, remote program, recording replay) continuously sends malformed/oversize `APC G`.
  - Evidence: The `terminate_apc` comment admits "assembler rejections already warned inside", i.e. a rejection always prints.

- **D08 — The `vte` `ignore` flag (parameter overflow/truncation) is dropped; overlong sequences execute with full semantics**
  - Location: `bitty/crates/bitty-vt/src/parser/dispatch.rs` (`csi_dispatch(..., _ignore, ...)`, `esc_dispatch(..., _ignore, ...)` both ignore the bit).
  - Symptom: `bounded.rs` documents "`vte` bounds parameter count (extra parameters are dropped and flagged via `ignore`)", but the dispatch side drops the flag: e.g. a 40-parameter SGR executes silently in its truncated form after `vte` truncation (e.g. a trailing `0` reset is lost), deviating from the true byte-stream semantics with no `Unknown`/truncation marker.
  - Trigger: CSI/ESC whose parameter count/intermediate bytes exceed the `vte` limit (trivial for fuzzers to construct).
  - Evidence: `_ignore` is unused in both `Perform` method signatures; there is no test in the repo for that flag.

- **D09 — Full screen emits one `FillRect` per cell with no run-merging of same-color backgrounds; full-screen scroll explodes vertices**
  - Location: `bitty/crates/bitty-render/src/grid.rs` (`GridRenderer::place_cell` unconditionally `push`es one background `FillRect` per visited cell).
  - Symptom: A 200×62 full screen produces 12400 fills (corroborated by the `ctx_0182_fullscreen_multi_chunk_requires_all_submits` test in `batch.rs`: 4 chunks, several MB of vertex bytes per frame). Every frame of a full-screen scroll repeats this cost, directly squeezing the PB-6 (≥40MB/s parse-and-render) and PB-4 (≤8ms p50 key-to-screen) budgets.
  - Trigger: Any full-screen damage frame (scroll, `ED 2`, alt-screen switch, `resize`).
  - Evidence: `place_cell` contains no merging logic keyed on neighboring-cell color/rectangle continuity; the comment only stresses "union of incremental frames equals full redraw" with no mention of merging.

- **D10 — `srgb8_to_linear` performs several `powf` calls per quad, tens of thousands per full-screen frame**
  - Location: `bitty/crates/bitty-render/src/batch.rs` (`srgb8_to_linear`; `emit_fill_quad`/`glyph_quad_bytes` call it via `rgba8_to_float4`).
  - Symptom: Each fill/glyph quad costs at least 3 channels of `powf(2.4)`; 12400 quads mean ~40k `powf` calls, millisecond-scale cost. The input domain has only 256 values, so a 256-entry `f32` LUT eliminates it entirely.
  - Trigger: Full-screen or large-area damage frames.
  - Evidence: Tests such as `rgba_bytes_decode_srgb_to_linear_light` pin the numeric semantics and can be reused directly as regression assertions after switching to a LUT.

- **D11 — `GlyphCache` clears everything when full, re-rasterizing repeatedly under a CJK working set**
  - Location: `bitty/crates/bitty-render/src/cache.rs` (`GlyphCache::glyph` performs `self.entries.clear()` when full).
  - Symptom: The default capacity 2048 only "covers a few screens of Latin glyphs"; a full CJK screen (tens of thousands of distinct glyphs × styles) easily overflows it, and every overflow discards everything including hot glyphs, producing a clear → re-rasterize → clear-again oscillation where rasterization degrades to O(n²).
  - Trigger: Full-screen CJK `cat`, mixed font sizes/styles.
  - Evidence: The comment admits "wholesale eviction … deterministic; per-entry LRU … marginal gain at terminal working-set sizes", but that claim only holds for Latin; the existing test is only a small capacity-4 determinism experiment (`wholesale_eviction_keeps_the_bound`) with no CJK-scale case.

- **D12 — `ESC n`/`ESC o` (LS2/LS3 locking shifts) are treated as `ESC N`/`ESC O` (SS2/SS3 single shifts)**
  - Location: `bitty/crates/bitty-vt/src/parser/dispatch.rs` (`esc_dispatch` maps both `N`/`n` to `G2` and both `O`/`o` to `G3`); `bitty/crates/bitty-term-state/src/charsets.rs` (`invoke` arms a single shift for G2/G3 unconditionally).
  - Symptom: When locking G2/G3 is required (e.g. some line-drawing applications), the charset applies to only the next printable character and then falls back automatically, garbling box-drawing over large areas.
  - Trigger: The peer sends `ESC n` / `ESC o`.
  - Evidence: The `charset_designation_and_single_shifts` test only covers `ESC N`/`ESC O` with no cases for `ESC n`/`ESC o`; the `charsets.rs` documentation itself hard-codes single-shot semantics for G2/G3.

- **D13 — Origin-mode CPR reply `row - scroll_region_top` has no saturation guard**
  - Location: `bitty/crates/bitty-term-state/src/state.rs` (`CursorPosition` branch of `request_device_status`).
  - Symptom: The normal path is masked by the per-action trailing `enforce_cursor_invariants`, but once an intermediate "cursor above scroll region under origin mode" state appears (any future handler missing a clamp can produce it), the `u16` subtraction underflows and panics (panics in release as well, not only debug).
  - Trigger: Requires a briefly broken invariant first; a fragility rather than an already-exploded bug.
  - Evidence: All other cursor clamps in the same file use `saturating_sub`/`min`/`clamp`; only this site subtracts bare.

- **D14 — Hyperlink table degrades permanently to no-link when full, until `FullReset`**
  - Location: `bitty/crates/bitty-term-state/src/state.rs` (table-full branch of `osc_hyperlink` returns `None`).
  - Symptom: Once `HYPERLINK_TABLE_MAX = 1024` fills up, all new links silently lose styling (fail-closed is itself reasonable), but old entries are never reclaimed even after scrolling out of view, so a long session's hyperlink feature is effectively switched off permanently.
  - Trigger: A long session accumulating more than 1024 distinct `(id, uri)` pairs (easy with `ls`/build logs containing links).
  - Evidence: The branch comment only says "degrade to no link", with no LRU/clear/reuse policy; `FullReset` is the only recovery path.

- **D15 — SGR `38;5` with a missing index defaults to black; truncated `38;2` still consumes 4 following parameters**
  - Location: `bitty/crates/bitty-vt/src/parser/sgr.rs` (`extended_color` semicolon path: `unwrap_or(0)`; the `Some(2)` branch returns a fixed consumption of 5).
  - Symptom: Truncated `CSI 38;5 m` is interpreted as `Indexed(0)` black instead of inert; `CSI 38;2;255;0;1 m` (one channel short, followed by bold `1`) swallows the genuine `1` as the blue channel while failing to decode, losing the bold.
  - Trigger: Truncated/corrupt extended-color sequences (peer bug, recording packet cut, fuzz input).
  - Evidence: The caller still `return`s 3/5 when `color_from_rgb` returns `None`; missing-parameter `38;5` fabricates an index via `unwrap_or(0)`.

- **D16 — Width `resize` performs 2–3 full re-layout passes, with per-logical re-layout inside the cursor-mapping loop**
  - Location: `bitty/crates/bitty-term-state/src/state.rs` (`State::resize` first builds its own full clone `old_logicals`, then calls `reflow_primary` to unwrap/rewrap again; then, to locate the cursor, calls `rewrap_one_logical` per entry of `old_logicals`).
  - Symptom: Under the limit configuration (100k scrollback rows × wide rows), a single width change involves hundreds of millions of cell clones and multiple `Vec` allocations, stalling the UI thread for seconds; `map_unit_to_rewrapped`'s linear re-layout makes cursor positioning itself O(full) as well.
  - Trigger: Width changes under large scrollback + large width (e.g. dragging back and forth between 200 and 80 columns).
  - Evidence: The three full loops in `resize` (`to_vec`/`trim_row_to_leads`/`rewrap_one_logical`) are all visible in source; the comment admits "Bounded: same work as reflow, resize-rare", but the bound is "full × constant passes", which is not small under the limit configuration.

- **D17 — A 64-batch-lagging `damage_since` returns tens of thousands of regions at once, and `plan_frame` merges them in O(n²)**
  - Location: `bitty/crates/bitty-term-state/src/state.rs` (`damage_since` with no merging and no cap); `bitty/crates/bitty-render/src/frame.rs` (`coalesce` fixed-point O(n²) scan, only safe for `n ≤ 256`).
  - Symptom: The other face of the same root cause as D01 — even without losing damage (caller happens to stay inside the window), 64 batches × 256 regions = 16384 rects are handed to `SnapshotDamage::new` → `plan_frame` at once, and the pairwise loop in `coalesce` can reach hundreds of millions of comparisons. The correct fix is to merge/cap on the `damage_since` side first (full screen once over the limit).
  - Trigger: High-throughput scenarios lagging dozens of batches behind on rendering (switching a background tab back to foreground while `cat` runs on a large file).
  - Evidence: `damage_since` only `extend_from_slice`s, with no sorting, no merging, and no `DAMAGE_MAX_REGIONS_PER_BATCH` constraint.

### P2 (robustness / API design / small correctness, fix opportunistically)

- **D18 — `compute_atlas_dirty` memcmps the whole atlas every frame (4MB/frame)**
  - Location: `bitty/crates/bitty-render/src/batch.rs` (`compute_atlas_dirty` compares row by row).
  - Symptom: With a 2048² atlas this scans 4MB per frame, ~240MB/s of pure comparison bandwidth at 60fps; the `ensure` side already knows whether any new glyph was placed this frame, so one dirty bit could skip the Clean decision.
  - Trigger: Every frame containing text. Effort S.

- **D19 — `GridRenderer::render` cannot actually fail, so the `Result` signature misleads callers**
  - Location: `bitty/crates/bitty-render/src/grid.rs` (`render`; `emit_glyph` maps `Err(_) =>` skip-and-count-blank).
  - Symptom: Rasterization failures are swallowed as "skip the glyph + increment a counter", `render` never uses `?`, so the caller's error-match arm is unreachable, yet callers must still write handling for an error that can never arrive; degraded frames are indistinguishable from normal frames at the type level.
  - Evidence: No error-propagation point exists in the `render` body. Effort S (return degradation statistics instead, or genuinely propagate the first raster error).

- **D20 — `soft_reset` sets `auto_wrap` to false, which is questionable against VT510 DECSTR**
  - Location: `bitty/crates/bitty-term-state/src/state.rs` (`soft_reset`).
  - Symptom: The comment says "autowrap reset" means false; but DECSTR semantics mean "back to the initial state", while the initial DECAWM is on (`Modes::default().auto_wrap == true`). If a VT510 item-by-item check finds DECSTR should not turn wrap off, applications relying on DECSTR will suddenly stop wrapping.
  - Trigger: The peer sends `CSI ! p`. The VT510 manual must be consulted first to settle it; effort S.

- **D21 — `char_cell_width` zero-width/wide table gaps**
  - Location: `bitty/crates/bitty-term-state/src/cell.rs` (`is_zero_width` lacks combining ranges such as U+1AB0–U+1AFF, U+1DC0–U+1DFF, U+20D0–U+20FF; `is_wide` lacks symbol ranges such as U+2600–U+26FF, U+2700–U+27BF, U+2B00–U+2BFF, U+1FA00+; `cp < 0x0300` unconditionally returns 1).
  - Symptom: Some combining marks are treated as occupying 1 cell (misplaced accents), and some symbols/emoji disagree with wcwidth on width (misalignment). The docs already declare this a "compact approximation, authoritative table pending the text RFC", hence P2, but the gaps should be listed item by item as a test matrix.
  - Trigger: The above code points. Effort M (pin the table + property tests).

- **D22 — Canonical hash omits the image store; `write_modes` omits saved kitty/mouse bits**
  - Location: `bitty/crates/bitty-term-state/src/state/hash.rs` (`state_hash` includes the primary modes' `kitty_keyboard` + two mouse items, but `write_modes(&save.modes)` writes only 12 bools; `images: ImageStore` never participates).
  - Symptom: Two states differing only in the primary-saved kitty/mouse hash identically; two states differing only in image placeholders hash identically. Replay determinism claims "same input → same digest", while collisions in the reverse direction weaken the hash as a state fingerprint (the `CANONICAL_HASH_VERSION` comment shows versions v2–v5 were bumped for similar omissions in the past).
  - Trigger: A `replay_determinism`-style test adding kitty/mouse + alt in/out combinations could observe a collision. Effort S (add the fields + bump to v6 + regression pin).

- **D23 — Private-mode `Unknown` report drops the final byte, so `?999h` and `?999l` are indistinguishable in telemetry**
  - Location: `bitty/crates/bitty-vt/src/parser/dispatch.rs` (the unmapped branch of `dispatch_mode` hard-codes `final_byte: 0, intermediates: [b'?', 0]`).
  - Symptom: Telemetry and recording replay cannot distinguish the enable/disable direction. Effort S (carry the `h`/`l` corresponding to `enabled`).

- **D24 — `OSC 52` query detection is too broad; `OSC 8` URIs containing `;` are truncated**
  - Location: `bitty/crates/bitty-vt/src/parser/dispatch.rs` (`osc_dispatch`: `rest.iter().any(|s| *s == b"?")`; hyperlink takes the single segment `rest.get(1)`).
  - Symptom: A selector segment of `?` with a non-empty data segment is misclassified as a read; a URI containing `;` keeps only its first segment. Both downstream paths are currently inert, so the practical impact is limited to recording semantics and future clipboard/link policy.
  - Effort S.

- **D25 — Non-APC bytes are fed to `vte` byte by byte; no passthrough batching**
  - Location: `bitty/crates/bitty-vt/src/parser.rs` (the non-APC branch of `advance` calls `state_machine.advance(&mut bridge, &[b])` once per byte).
  - Symptom: One `Perform` dispatch overhead per call; the APC pre-scan itself is also byte-by-byte. To hit the PB-6 40MB/s target, pure text/pure control runs should first be cut out with `memchr` and fed to `vte` in batches.
  - Effort M (including benchmark proof).

- **D26 — Software and headless compositing allocate one `Vec` mask per glyph**
  - Location: `bitty/crates/bitty-render/src/software.rs` (`draw_list_onto` atlas branch does per-glyph `Vec::with_capacity` + row-by-row copy); the headless branch of `bitty/crates/bitty-render/src/gpu.rs` follows the same pattern.
  - Symptom: The software path heap-allocates once per glyph per frame; it could blit row by row directly or reuse a row buffer. The software path is opt-in (`sw-fallback`), hence P2.
  - Effort S.

- **D27 — Debug assertions scan the whole grid + scrollback on every action**
  - Location: `bitty/crates/bitty-term-state/src/state/invariants.rs` (`check_invariants` walks every cell of both screens + width/monotonicity of all scrollback rows); call sites are the trailing `debug_assert`s in `finalize_batch` and `resize`.
  - Symptom: Under 10k scrollback rows, debug test/dev runs scan hundreds of thousands of cells per action, making proptests very slow. Release is unaffected.
  - Effort S (sample at lower frequency or full-check only in test exhibits).

- **D28 — Unknown SGR subcodes are silently dropped with no telemetry**
  - Location: `bitty/crates/bitty-vt/src/parser/sgr.rs` (`_ => 1`).
  - Symptom: `CSI 6 m` (rapid blink), `CSI 53 m` (overline), etc. are indistinguishable from no-ops, leaving no data for future extension scheduling.
  - Effort S (count unknown subcodes in telemetry or surface `Unknown`).

- **D29 — `RenderError` is flattened to `String` upstream, losing the `source` chain**
  - Location: `bitty/crates/bitty-render/src/error.rs` (`flatten_rasterizer` keeps only the `Display` text).
  - Symptom: GPU/font-stack failures lose structured context during triage; `InvalidInput { reason: &'static str }` goes to the other extreme (it cannot even echo dimensions, although the comment weighs "preventing malicious input from inflating error allocations").
  - Effort S (keep `#[source]` or graded error payloads).

## Test gaps

- **bitty-vt**
  - `ESC _ ... ST` split across packets (`ESC \` cut by a packet boundary, `BEL`/`0x9C` terminators, `CAN`/`SUB` aborts, trailing dangling `ESC` at packet end) has only normal-path cases, lacking a packet-boundary fuzz matrix.
  - No byte-level regression for the "do not intercept" policy on C1 `APC` (`0x9F`) overlapping UTF-8 continuation bytes (e.g. 🎉 contains `0x9F`) (the comment states the motivation, no test pins it).
  - No cases at all for the `vte` `ignore` flag (overlong parameters/oversize OSC); the wrong semantics of D08 have no guard.
  - No cases for truncated SGR shapes (`38;5` missing parameter, `38;2` missing channel, `38:2::r:g:b` empty colorspace, unknown subcodes such as 6/53); D15/D28 have no net.
  - No cases for `ESC n`/`o` (LS2/LS3) (the existing `charset_designation_and_single_shifts` only reaches `ESC N`/`O`); D12 has no net.
  - No cases for the shapes `OSC 52` with a `?` selector but non-query, `OSC 8` URI containing `;`, `OSC 133 D` with extra segments; D24 has no net.
  - No cases for the memory gate on huge unknown/`f=100` Kitty payloads (the existing `oversize_claim_rejected_before_emit` only covers the claim check for `f=32`); D06 has no net.
  - No assertion on stderr behavior of the reject path (tests cannot even discover the log amplification of D07).
  - No pin on whether `;`-separated flags such as `7727;1` are Kitty fragments or standalone mode `1` (the `;`-consuming loop in `kitty_flags_from_sub` lacks a decision-documenting test).
- **bitty-term-state**
  - `damage_since` over-window behavior: the existing proptest excludes overflow via `actions.len() < 64` (`replay_determinism.rs`); the correct semantics of D01/D17 (overflow means full) have no positive cases.
  - No case for whether `Grid::resize` preserves `wraps` after an equal-width height change; D04 has no net.
  - `erase_range_in_row` double-sided cross-pair: both existing tests are single-sided; D03 has no net.
  - Zero-width/wide matrix: the three existing cases in `cell.rs` (one each for ASCII/CJK+emoji/combining) are far from covering the D21 gap regions; whole-cluster behavior for ZWJ multi-scalar clusters (e.g. family emoji) has no cases (shaping is deferred, but the exact shape of the "multi-cell approximation" should be pinned first).
  - No case for permanent degradation after the hyperlink table fills; D14 has no net.
  - No case for whether `DECSC` save/restore includes cursor style/visibility (`SavedCursor` has neither field — design or omission, nobody asserts it).
  - No manual cross-check test for `soft_reset` `auto_wrap=false` against VT510; D20 has no net.
  - No adversarial case for the `request_device_status` origin underflow; D13 has no net.
  - No xterm-compatibility control case for `SGR 21` (doubly underlined vs bold-off).
  - No performance cap for width-changing `resize` under the limit configuration (100k scrollback × 1000 columns); D16 has no net.
  - `search` large-grid performance: existing search tests all use small 80×24 grids with no large-grid cases; D05 has no net.
  - Canonical hash: no "primary-saved kitty/mouse only difference → different hash" / "image-store-only difference → different hash / documented exclusion" cases; D22 has no net.
  - Nobody cares about the debug cost of `check_invariants` itself; D27 has no net.
- **bitty-render**
  - Post-intra-frame-eviction validity of earlier glyphs: the existing `atlas_eviction_is_wholesale_and_deterministic` only asserts determinism (two runs agree), not that "all glyphs of an eviction frame still sample correctly"; D02 has no net.
  - CJK-scale working-set glyph-cache oscillation: the existing `wholesale_eviction_keeps_the_bound` uses capacity 4 only, with no CJK/large-capacity cases; D11 has no net.
  - Background-fill run merging: no count-style case such as "an all-white screen produces only ~row-count fills"; D09 has no net (the `ctx_0182` test only pins total chunk count, not fill-count semantics).
  - No benchmark for the full-scan cost of `compute_atlas_dirty`; D18 has no net.
  - `render` `Err` path: swallowed inside `emit_glyph`, so the branch is actually unreachable and no case can reach it; D19 has no net.
  - True-GPU path: `tests/gpu_integration.rs` etc. require `BITTY_RENDER_GPU_TESTS=1` + a real driver/w windowing system and are skipped by default in CI; the multi-chunk submit in `pipeline.rs` (CTX-0182 fix) has unit coverage, but end-to-end regressions such as "full-screen blue-background dialog on a real card" still rely on manual runs.
  - The `sw-fallback` feature is off by default, so default CI neither compiles nor tests `software.rs` (stated in the module-header comment); the per-glyph allocation of `draw_list_onto` (D26) and three-way GPU/headless synthesis consistency lack a default gate.
  - Cursor visuals and scrollback-viewport rendering are "explicitly deferred" (module docs in `grid.rs`); having no tests is by design, but they should be marked deferred explicitly in the test matrix to avoid being misread as covered.
  - sRGB LUT equivalence: the existing `srgb_round_trip_is_byte_exact` can be reused directly as the LUT regression, but the LUT itself does not exist yet (D10).
