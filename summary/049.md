# 049 — Wheel Context Compiler Design

- Status: Partial — `bitty-ai`-owned conclusions distilled as a draft discussion synthesis in `bitty-ai-docs` (`specifications/research/research-distillation-048-049-bitty-ai.md`, accepted through PR bitty-ai#120, merged); captures in other corpora (Wheel context-compiler, provider-cache owners) not verified — treat remaining sub-conclusions as owner-pending
- Date: 2026-09-18 (archive receipt; the original discussion contains no explicit date)
- One-liner: Place a real Context Compiler between the Agent Runtime and the LLM provider — ingest, normalize, classify, dedup, retrieve, reduce, budget, cache-plan, and provider-lower every turn — over Cold/Warm/Hot layers, six stability zones, and four cache kinds.
- Background / Problem:
  - Follow-up to the quality record: naive harnesses concatenate messages, tools, and files until a threshold and then summarize, so sessions grow dirty context, break caches, and degrade the agent the longer they run.
  - Three conflated things must be separated first: Context Storage (near-unbounded event and object retention), Active Context (what this inference sees), and Prompt Cache (provider-side prefix reuse).
- Key conclusions / Decisions:
  - Adopt Cold (full history, logs, transcripts — never resident by default), Warm (indexed and re-fetchable: AST/LSP indexes, repo maps, checkpoints, capability metadata, decisions), and Hot (this inference only) layering; the compiler continuously decides what enters the Hot set.
  - Compile to a Context IR of typed units carrying kind, source, priority, relevance, authority, trust, freshness, lifetime, token estimate, cacheability, stability, content hash, dependencies, and provenance — never raw string concatenation.
  - Separate content from layout: one IR with per-provider lowering backends, so provider cache mechanics (breakpoints, keys, explicit content APIs) stay out of the agent runtime.
  - Order context by stability zone (provider/model contract, Wheel core, project context, task state, working set, current turn) and maintain a Merkle-chained cache tree so a working-set change invalidates only the dynamic suffix.
  - Serialize canonically (stable tool order, key order, whitespace, section order); keep volatile data (timestamps, request ids, branch, resource readings, raw status) out of the stable prefix; prompt position follows inverse volatility.
  - Never trade quality for hits: utility ranks task quality above relevance above cache hit above token cost; the admission-score sketch weights relevance, importance, freshness, and authority minus noise and token cost, with only a small cache tiebreak bonus.
  - Resolve authority before inference (system policy, current user instruction, project rules, task decisions, retrieved docs, old summaries, model notes) and drop contradicted lower-authority content instead of asking the model to arbitrate.
  - Make code context content-addressed (path, symbol, range, file hash, revision) with automatic staleness invalidation, and dedup semantically identical rules into one derived unit with retained provenance.
  - Reduce tool results in three levels (deterministic scrubbing, structural parsing into typed summaries, LLM semantic compaction only for the unstructurable remainder) and run four compaction modes (continuous reduction, continuous eviction, checkpoint compaction, emergency compaction).
  - Keep summaries traceable (compressed view plus evidence pointers with rehydration) and expose addressable Context Pointers the model can inspect on demand instead of preloading bulk logs.
  - Run an explicit pass pipeline (ingest, normalize, classify, staleness check, retrieve, authority resolution, dedup, reduction, ranking, budgeting, cache planning, provider lowering) with telemetry feeding back into future compilations.
  - Budget below the model window (soft, hard, and emergency limits; start small and expand on evidence), split pinned, flexible, and reserve quotas so results and reasoning always have room, and distinguish four caches (provider prompt, artifact, retrieval, compaction).
  - Abstract provider cache capabilities (prefix/explicit modes, breakpoints, TTL, invalidation rules), namespace caches by provider, model, protocol, reasoning profile, toolset, and prompt versions, version compiler artifacts, and prefer a small static core toolset with deferred discovery to protect the stable prefix.
  - Ship strong observability (status-bar context and cache figures, per-section token breakdowns, inclusion reasons, compile traces recording additions, reductions, evictions, and hits); a worked bug-fix example shows raw session knowledge growing while the hot view stays small and mostly cached.
  - Proposed module split: store (events, artifacts, checkpoints), index (code, docs, semantic), compiler (retrieval, ranking, dedup, reduction, budgeting, authority), cache (artifact, retrieval, compaction, provider), backend (per-provider).
