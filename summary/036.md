# 036 — Pane Environment Variables and Inheritance

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-09-15 16:48
- One-liner: Inherits pane environments through prompt-time sync, usable by agents without seeing secrets.
- Background / Problem:
  - Shells differ in export syntax, so tracking environment changes by parsing user input cannot be complete.
  - New panes already inherit the working directory from the focused pane; whether transient environments follow suit needs a rule.
  - Agents need to perceive pane environments without touching sensitive values.
- Key conclusions / Decisions:
  - Environments are split into process, config, launch, and runtime layers; new panes build their launch environment along the inheritance chain.
  - Sync runs through a helper child process at each return to the prompt, without parsing script semantics.
  - Core builds pane environment snapshots and unifies them with working directory, command, and prompt into shell state.
  - New panes inherit the source directory and environment by default, with a clean mode plus explicit override support.
  - Agents get a redacted view by default where sensitive keys show presence only; execution can reuse the environment without reading plaintext.
  - No on-disk persistence by default; environments rebuild from system and config after restart, and only exported variables are synced.
