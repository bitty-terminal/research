# 047 — Caller Attribution for Provider Calls

- Status: Open — conclusions not yet captured in any `*-docs` repo; destinations proposed below (owner-pending)
- Date: 2026-09-17
- One-liner: OpenRouter's Apps ranking is caller-declared attribution (HTTP-Referer/X-Title aggregated per model x app), not gateway scanning — so Bitty must declare caller identity at the request layer; plus the LLM-provider layer splits out of Wheel as its own Model Infrastructure plugin (Wheel manages Agent, plugin manages Provider/Auth/Model/Thinking/Routing/Catalog).
- Background / Problem:
  - Owner's analysis of an OpenRouter model page: the Apps column ("Public apps that send the most traffic to this model") counts only traffic that declares identity via request headers (HTTP-Referer as unique ID, X-Title display name, X-Categories, X-App-Visibility:hidden opt-out); calls without Referer fall into unattributed/private traffic; tokens = prompt + completion from upstream tokenizers, aggregated per UTC day in real time; 62.6B tokens = attributed public-app traffic in-window, not global usage. Listed apps (Hermes Agent, Claude Code, Cline, ZCode) are Harness/Agent products whose clients self-report identity by default.
  - Owner requirement: this attribution must enter Bitty's future design, otherwise callers cannot know where usage was spent.
  - Commander verification (bitty-ai, read-only): TurnRequest (`provider.rs:411-430`) carries model/messages/context_refs/tools/budget/timeout/now_ms/sampling — no caller/app identity field. The only real HTTP emitter, LocalProvider `http_round_trip` (`local_provider.rs:611-683`), sends Host/Content-Type/Content-Length/Connection plus optional Authorization — no Referer/Title/identity. Cost controls exist but are internal units (agent cost fuse via `round_usage`, `agent.rs:542-559,976-987`; routing `estimate_cost`, `selection.rs:747-756`), not usage attribution. Closest spec: Router transport in `provider-plugin-boundary.md:130-132` (gateway as one provider entry with own accounting) — but no caller-identity declaration/transit rule.
- Key conclusions / Decisions:
  - Add an optional caller-attribution field on TurnRequest (app id plus optional title/category); adapters translate it into gateway headers (HTTP-Referer/X-Title); absent means explicitly unattributed (local/private), never forged or defaulted — mirroring `sampling: None` undeclared-flows-untouched (`provider.rs:427-429`).
  - Boundaries: identity is not credential (secret invariant, `provider-plugin-boundary.md:194`; identity goes to headers, never prompt/context; bounded and scrubbed before typed surfaces per the `bridge.rs` bound_reason precedent); declaration-only, no settlement (tokenization/pricing is gateway/upstream business; Core guarantees declared/transited/auditable); excluded from cache keys and routing like sampling (`cache_key.rs` precedent); wired per adapter (LocalEndpoint needs none; real HttpApi/Router adapters wire it when built — no code for imagined gateways, generalize-from-two-implementations per 046).
- LLM Infrastructure plugin split (appended 2026-09-17, second half of the origin record):
  - Owner proposes LLM configuration as a separate plugin: vendor APIs (OpenAI/Anthropic/Gemini/Bedrock/Azure Foundry/Vertex/OpenRouter/OpenCode Zen/Go/coding-plan and Claude/ChatGPT/Google-One-style subscriptions reused in Wheel), thinking gears, model management and catalog sync — referencing omniroute (local one-click model management) and oh-my-pi (fullest harness-side LLM management, beyond OpenCode /connect). Wheel keeps only thin local LLM handling and focuses on Agent management (many custom agents); model management is decoupled and reusable across plugins, as with Pi Agent.
  - Record agrees and hardens it: Wheel manages Agent, never Provider; the LLM plugin manages Provider/Auth/Model/Thinking/Routing/Catalog, never Agent. Wheel sees only a unified Model (id/capabilities/thinking levels); agents bind model + thinking + fallback + budget while auth mechanics (API key/OAuth/subscription/AWS/Google ADC/local Ollama) stay hidden — the abstraction boundary.
  - Plugin scope: Provider Registry, Authentication as Auth Strategy (api_key/oauth/subscription_oauth/aws_credentials/google_adc/bearer/none — officially allowed/stable flows only, no cookie theft or credential scraping; subscription adapters must be replaceable, cf. Google AI Pro/Ultra migration to Antigravity), Model Catalog with discovery/sync (models.dev, oh-my-pi catalog/discovery, OmniRoute 200+ providers as references), Protocol Adapters, Model Normalization (oh-my-pi minimal..max reasoning mapping with clamp/fallback), Routing (fallback/alias/preference), Usage (token/quota/rate/cost). Provider-vs-Model separation (same weights via openai/azure-openrouter/custom-company differ in endpoint/auth/quota/price). Unified Model Capability plus Model Profiles (@fast/@cheap/@smart/@deep/@vision/@coding, oh-my-pi model-roles precedent) so agent files never change on provider swaps.
  - Three-layer boundary: Bitty Core (plugin runtime/IPC/Secure Secret Store/permission/streaming) → Official LLM Plugin → Model API → Wheel/future agents/other plugins. Secret Store belongs to Core (opaque handles, never per-plugin plaintext token files). Lua owns the control plane first; heavy machinery (SSE/OAuth/HTTP2/retry/proxy/TLS/refresh/streaming JSON/concurrency) may sink to a native Provider ABI later — the product boundary is what matters.
  - Anti-premature move shared with 046: no Universal Agent API for imagined agents; generalize from two real implementations. The split should be decided before the Wheel MVP writes its first OpenAIProvider/AnthropicProvider/ClaudeOAuth, or extraction later will be painful.
- Destination: proposed owner-pending — (1) TurnRequest attribution-field design into bitty-ai-docs (new draft or provider-plugin-boundary follow-up; AI-XXXX implementation only when a real HTTP/Router adapter lands); (2) Wheel/app-level default identity (e.g. Wheel's Referer/Title) decided with the Wheel MVP, not here; (3) LLM Infrastructure plugin boundary (Wheel-manages-Agent / plugin-manages-Provider, Auth-Strategy auth, Model Profiles, Core-owned Secret Store) reconciled against the existing two-level plugin model in `provider-plugin-boundary.md:141-166` — new draft or follow-up section, not re-decided here. This document creates no AIQ or OQ identifier and closes none.
- Open items: owner approval of the field shape; Wheel's public app identity string; whether unattributed calls stay allowed by default; owner approval of the LLM-plugin split and the Model Profile vocabulary; `origin/047.md` stays unrenamed until the captures land.
