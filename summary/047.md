# 047 — Caller Attribution for Provider Calls

- Status: Open — conclusions not yet captured in any `*-docs` repo; destinations proposed below (owner-pending)
- Date: 2026-09-17
- One-liner: OpenRouter's Apps ranking is caller-declared attribution (HTTP-Referer/X-Title aggregated per model x app), not gateway scanning — so Bitty must declare caller identity at the request layer, or usage can never be attributed to where it was spent.
- Background / Problem:
  - Owner's analysis of an OpenRouter model page: the Apps column ("Public apps that send the most traffic to this model") counts only traffic that declares identity via request headers (HTTP-Referer as unique ID, X-Title display name, X-Categories, X-App-Visibility:hidden opt-out); calls without Referer fall into unattributed/private traffic; tokens = prompt + completion from upstream tokenizers, aggregated per UTC day in real time; 62.6B tokens = attributed public-app traffic in-window, not global usage. Listed apps (Hermes Agent, Claude Code, Cline, ZCode) are Harness/Agent products whose clients self-report identity by default.
  - Owner requirement: this attribution must enter Bitty's future design, otherwise callers cannot know where usage was spent.
  - Commander verification (bitty-ai, read-only): TurnRequest (`provider.rs:411-430`) carries model/messages/context_refs/tools/budget/timeout/now_ms/sampling — no caller/app identity field. The only real HTTP emitter, LocalProvider `http_round_trip` (`local_provider.rs:611-683`), sends Host/Content-Type/Content-Length/Connection plus optional Authorization — no Referer/Title/identity. Cost controls exist but are internal units (agent cost fuse via `round_usage`, `agent.rs:542-559,976-987`; routing `estimate_cost`, `selection.rs:747-756`), not usage attribution. Closest spec: Router transport in `provider-plugin-boundary.md:130-132` (gateway as one provider entry with own accounting) — but no caller-identity declaration/transit rule.
- Key conclusions / Decisions:
  - Add an optional caller-attribution field on TurnRequest (app id plus optional title/category); adapters translate it into gateway headers (HTTP-Referer/X-Title); absent means explicitly unattributed (local/private), never forged or defaulted — mirroring `sampling: None` undeclared-flows-untouched (`provider.rs:427-429`).
  - Boundaries: identity is not credential (secret invariant, `provider-plugin-boundary.md:194`; identity goes to headers, never prompt/context; bounded and scrubbed before typed surfaces per the `bridge.rs` bound_reason precedent); declaration-only, no settlement (tokenization/pricing is gateway/upstream business; Core guarantees declared/transited/auditable); excluded from cache keys and routing like sampling (`cache_key.rs` precedent); wired per adapter (LocalEndpoint needs none; real HttpApi/Router adapters wire it when built — no code for imagined gateways, generalize-from-two-implementations per 046).
- Destination: proposed owner-pending — (1) TurnRequest attribution-field design into bitty-ai-docs (new draft or provider-plugin-boundary follow-up; AI-XXXX implementation only when a real HTTP/Router adapter lands); (2) Wheel/app-level default identity (e.g. Wheel's Referer/Title) decided with the Wheel MVP, not here. This document creates no AIQ or OQ identifier and closes none.
- Open items: owner approval of the field shape; Wheel's public app identity string; whether unattributed calls stay allowed by default; `origin/047.md` stays unrenamed until the captures land.
