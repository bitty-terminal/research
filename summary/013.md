# 013 — Terminal Panorama Architecture and Embodied Multi-Agent Workspace

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-09-13 17:41
- One-liner: From theme hot-reload to rich text, plugin reuse, and a native AI workspace, establish the programmable terminal workspace panorama.
- Background / Problem:
  - Theme adaptation, rich-text rendering, plugin reuse, session restore, multimedia extension, and AI collaboration need unified architectural homes.
  - The core must avoid bloat while supporting cross-platform reach, package management, and multi-agent extension.
  - The long-term division of labor between terminal and workspace, mechanism and policy, native and plugin needs an answer.
- Key conclusions / Decisions:
  - Adopt the guiding principle of small core, stable API, and composable everything, evolving from terminal emulator to programmable terminal, workspace, and then extensible application shell.
  - Drive theme syncing with external palette generation plus atomic IPC reload, applying updates in a single render pass to avoid flicker and resets.
  - Place rich-text parsing and layout in plugins or upper layers, keep graphics primitives and rendering mechanisms in the core, and handle bidirectional text only at the presentation layer.
  - Establish four reuse layers: pure Lua, system CLI, plugin services, and native helper processes; plugins must declare external tools and invoke them only through controlled spawning.
  - Follow system directory conventions for config, data, state, cache, and communication credentials; forbid hard-coded secrets in favor of environment references or system keyrings.
  - Keep session restore natively in the core, with the core owning storage and scene restoration and plugins owning named sessions and selection UI; high-frequency visualization must use separate panels or isolated layers to avoid full-screen repaints.
  - Divide built-in plugins by mechanism versus policy, with mechanisms in the core and policies in plugins; forbid in-process dynamic library loading and support only external subcommands and out-of-process helpers.
  - Give each plugin an isolated virtual machine, forbid direct cross-plugin references, and share services through the host service bus; standardize selector, statusline, and context provider contracts.
  - Move from a Neovim-style editor toward an Emacs-like extensible environment, where panels are not terminals; AI converges on only three mainstream model protocols, with vendor presets and agent orchestration in Lua.
  - Build the native workspace around a scene tree, side inspector, graphics nodes, and a panel event bus; use an office-floor workstation metaphor for multi-agent work, sharing workspace state to reduce context hauling.
  - Stage the roadmap in four phases: mechanism foundations, plugin and provider ecosystem, programmable workspace, AI and multi-agent ecosystem.
