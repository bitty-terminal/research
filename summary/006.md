# 006 — Differentiating Hard Problems and Ten Plugin Questions

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-08-30
- One-liner: Prove the terminal foundation first, then discuss the plugin ecosystem.
- Background / Problem:
  - Bitty is in pre-research hardening; architecture exists but terminal correctness is not yet proven by dogfooding.
  - The plugin system risks growing too big too early; high-risk questions need locking in advance.
  - Need to answer the true differences versus Alacritty, Ghostty, WezTerm, WaveTerm, and Warp.
- Key conclusions / Decisions:
  - Identity lies in strict layering: small core, native runtime, programmability, structured control, observability, performance budgets.
  - The hardest problems are terminal compatibility, Unicode and IME, view and layout separation, generic Panels, rich-UI coexistence, cross-platform support, and staying strong yet light.
  - The biggest plugin API risk is designing too much too early; declarative UI is the hardest part.
  - Lua is not treated as a true security sandbox; the capability system must be strict.
  - Plugins must be truly uninstallable; the event system stays out of hot paths, with cold paths using bounded queues and quota-based drops.
  - Plugin dependencies go through service interfaces and version constraints, never direct imports of another plugin's internals.
  - Package management covers install, lock, rollback, verification, signing, and provenance; updates commit transactionally.
  - First-party plugins strictly consume the public API; zero are enabled by default; packaging includes only the base experience.
  - Work order: terminal truth, real rendering, usable terminal, dogfooding, view layout, plugin API, official plugins, rich ecosystem.
  - Shift from architecture-first to dogfooding-first.
- Destination: bitty-terminal-docs, bitty-plugins-docs (terminal foundation versus plugin protocols split across both)
- Open items:
  - Concrete performance budget numbers await measurement.
  - Declarative UI proposal is not yet finalized.
