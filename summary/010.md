# 010 — Bitty AI Differentiation and Context Invariants

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-09-13
- One-liner: Spatial multi-agent plus minimal-sufficient context.
- Background / Problem:
  - The market splits into single-line CLI, heavy IDE embedding, and pure background; Bitty must explain a fourth path.
  - Build output floods screens, child agents are black boxes, permission roles are coarse, evidence is hard to trace.
  - Early token-saving numbers lack baselines and should not be architecture goals.
- Key conclusions / Decisions:
  - Differentiation fixed as spatial multi-agent workspace: native tiling, multi-Panel collaboration, hard isolation, semantic throttling.
  - Panel is not an agent; output compression is not lossless; roles are not agents.
  - Context invariant: give models minimal-sufficient information while always keeping a path back to full evidence.
  - Context engine does source selection, ranking, compression, budgeting, and assembly, each item carrying source, freshness, weight, cost, and trust.
  - Project index goes beyond source-tree scanning, keeping traditional search; structured results are preferred over brute-force screen capture.
  - Evidence chain added: every conclusion traces back to runs, tool output, commits, and query sources; answers can jump to the evidence panel.
  - Spatial collaboration is hard in inter-agent message protocols; LSP tooling serves only as adapters, diagnostics never replace real builds.
  - Capabilities split in two layers, with role permission isolation; multi-agent difficulty lies in message protocols, not panels.
  - Conceptually split into core, runtime, model, context, tools, execution, code, protocol, editing, policy, observability, and adapter layers.
  - Land the single-agent read-think-change-verify pipeline first, then capability sandbox, multi-agent, and spatial UX.
  - CarryCtx fixed as backend, not required dependency; LSP access layer treats external management tools as adapters only.
- Destination: bitty-ai-docs (inference engine and context architecture belong to the AI repo)
- Open items:
  - Saving ratios need baseline-backed measurement.
  - Atomic patches versus workspace overlay proposal is undecided.
