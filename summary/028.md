# 028 — Runtime Structure Review and Deduplication

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-09-15 00:30
- One-liner: Remove empty shells and duplicate implementations, fix identity ownership.
- Background / Problem:
  - Empty placeholder packages contradict implementation portraits, forming a self-inconsistent package structure.
  - The experimental slice and the new runtime each keep a provider, session, and tool implementation.
  - Generic protocols and runtime define same-named but different-meaning identities and tools.
  - Model registry ownership, permission-tier semantics, and doc status have drifted.
- Key conclusions / Decisions:
  - Delete empty placeholder core packages, keep runtime and slice, splitting again only along real boundaries later.
  - Demote the slice to an integration harness keeping only bridges and fixtures, reusing the real runtime.
  - Distinguish protocol identity from runtime instance, single call, session, and execution identities to avoid same-name confusion.
  - Reuse the generic vocabulary for tool definitions; runtime adds only authorization and scheduling semantics without inventing new protocols.
  - Model machinery belongs to the agent side, network and credential host duties to the terminal side, joined by a bridge layer.
  - Permission tiers are only policy presets, not authorization proofs; real authorization uses capability sets with consent ledgers.
  - Duplicate tool registration names fail closed, with normalized scope references.
  - Sync self-description with portrait state; doc maps must not hardcode volatile commit snapshots.
  - Use disposition wording inside drafts, reserving accepted and normative wording for truly frozen content.
  - Keep the giant umbrella architecture as draft, letting narrow contracts lead; split and freeze small contracts incrementally.
  - Target shape is runtime, bridge, and slice layers, with terminal core unaware of models and agent workflows.
