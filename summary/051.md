# 051 — Git-Inspired Context, Compaction, and Multi-Agent Design

- Status: Partial — `bitty-ai`-owned conclusions distilled as a draft discussion synthesis in `bitty-ai-docs` (`specifications/research/research-distillation-050-051-bitty-ai.md`, accepted through PR bitty-ai#120, merged); captures in other corpora (Wheel context-storage owners) not verified — treat remaining sub-conclusions as owner-pending
- Date: 2026-09-18 (archive receipt; the original discussion contains no explicit date)
- One-liner: Model Wheel context on Git principles — immutable content-addressed objects in a DAG with checkpoints, branches, typed merges, refs, reflog, GC, and packfiles — and compile the active context from history instead of maintaining a growing transcript.
- Background / Problem:
  - Append-only message lists conflate full session history with working context; compaction-as-deletion loses decisions; copying whole transcripts to subagents is wasteful; session stores grow without bound.
  - Git already solves the analogous problem set (full history plus current snapshot plus cheap references), so the record borrows its design principles rather than its commands.
- Key conclusions / Decisions:
  - Replace the message list with a context DAG of typed objects (artifact, tree, checkpoint, summary, decision, task, result) addressed by content hash, gaining immutability, dedup, integrity, and cache reuse.
  - Repeated reads of unchanged files resolve to one stored artifact referenced many times, instead of duplicated tokens per read.
  - Checkpoint as commit analog (context tree, parent, task state, decisions, evidence, agent); compaction moves HEAD to a higher-level snapshot while history stays reachable — changing the visible view, never destroying history.
  - HEAD plus a context log for the session; branches for hypothesis exploration and subagents that share only a parent ref plus deltas instead of copied transcripts.
  - Merges combine code, decisions, task state, evidence, and context with explicit typed conflicts (e.g. competing root-cause hypotheses stay pending) instead of silent LLM summarization.
  - Cherry-pick single findings across branches for clean subagent isolation; share object refs between agents and expand lazily; rebase long-lived agents onto newer checkpoints with staleness and conflict detection.
  - Bind context branches to version-control branches, worktrees, agents, and panels for unified isolation; manage task, agent, checkpoint, and session state through a refs hierarchy rather than relational joins.
  - Recover from bad compactions, merges, or checkpoint moves via reflog restore; reclaim unreachable objects with mark-and-sweep GC from refs, pins, and active sessions plus grace periods, and pack small objects (with delta compression) in the background.
  - Key artifact, retrieval, and compaction caches by content hashes for clean invalidation; keep the semantic object store strictly separate from provider KV caches (DAG, compiler, canonical serialization, provider prompt, cache).
  - Treat the Context Compiler as checkout producing the active view from HEAD, and model multi-agent collaboration itself as a DAG with parents per node for natural parallelism, merging, reuse, and provenance.
  - Adopt user-facing Git vocabulary (checkpoint, branch, merge, rebase, gc, ref, HEAD, worktree; user-level artifact, context, and object naming) with a matching CLI sketch, plus context diff across checkpoints and per-type merge semantics.
  - Closing principle: Wheel maintains a content-addressed task history and compiles conversations from it.
