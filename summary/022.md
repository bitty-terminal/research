# 022 — Core-Lua Layering and Context Compression

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-09-14 18:21
- One-liner: Mechanisms in core, workflows in plugins, context compressed by view.
- Background / Problem:
  - Slash commands are proliferating with an unclear boundary between core and plugin implementations.
  - Full-history rewrites during compression cause token sawtooth fluctuation and loss of continuity.
  - Injecting full tool and MCP schemas into context causes severe schema bloat.
- Key conclusions / Decisions:
  - Separate command control plane, tool data plane, and skill-composed behavior; core implements mechanisms only, policies and workflows belong to plugins.
  - Sessions, context, tasks, agents, tools, models, permissions and other primitives go in core; review, planning, loops, goals and other workflows go to official plugins.
  - Core includes model-facing basic tools for read/write, retrieval, symbols, execution, language services, and task spawning; advanced Git, browser, and external integrations go via plugins or external service bridges.
  - Execution settles through headless panels and panel-log storage; context keeps only references and structured results.
  - Sessions are immutable facts; context is only their projection, produced by a dedup, substitution, externalization, summarization, range-compression, and trimming pipeline.
  - Compression has five levels: structured output at source, lossless mechanical trimming, range-selected compression, global compaction, and remote or provider-native compression.
  - Compaction records boundaries and token counts before and after as entries without deleting original sessions; continuous maintenance and emergency compaction coexist.
  - Compression backends are abstracted as pluggable capabilities, automatically selecting native, cheap remote, or local models per provider.
  - Context entries carry their own retention policy with pinned, recent, normal, and ephemeral tiers plus plugin intervention.
  - Context usage is shown in a panel UI with per-category view, compress, discard, pin, and inspect actions.
  - External service tools lazy-load: brief intro first, full schema only on demand; skill core handles only discovery, parsing, and invocation.
- Destination: bitty-ai-docs primary, panel and statusline parts in bitty-terminal-docs
- Open items: None
