# 029 — Network-Free Core and Controlled Extension

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-09-15 00:48
- One-liner: Core stays offline, extensions cross controlled boundaries.
- Background / Problem:
  - If the terminal core directly depends on network stacks, it inherits protocol, proxy, and certificate complexity.
  - Plugin installs via archive download would need redirect, checksum, and resume handling.
  - If plugin networking grants arbitrary command execution, privileges are too broad to audit.
- Key conclusions / Decisions:
  - Keep terminal and agent cores free of network dependencies; networking lives only behind package management, model providers, and plugin capability boundaries.
  - First plugin version supports only local and code-repository sources, calling system code-management tools without adding download tools or embedded implementations.
  - Separate running from package management; missing tools produce errors guiding manual placement without breaking the main terminal.
  - Abstract package sources as an extensible interface, adding registry and archive sources later; registries do metadata discovery only, bodies still come from sources.
  - First registry version also uses code-repository caches for local search with explicit updates.
  - Later network capabilities become standalone packages or feature flags, keeping default builds network-stack free.
  - Plugin networking goes through host-controlled interfaces, reusing system download tools at first, with interface separated from implementation for later replacement.
  - Plugins declare site and method allowlists, confirmed explicitly at install, rejected when exceeded; sensitive credentials use a controlled secrets interface.
  - Split the model layer into abstraction, provider, and transport, unifying internal requests and events while providers absorb interface differences.
  - Plugins and models may share transport implementations but not permission models; the former runs sandboxed while the latter is a trusted component.
  - Local-domain sockets are local IPC, not networking, and do not violate the network-free core constraint.
  - Establish invariants: core never initiates internet connections, plugin networking needs explicit least-privilege declarations.
