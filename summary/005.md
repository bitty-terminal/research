# 005 — Terminal Ecosystem Survey and Key References

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-08-30
- One-liner: Five routes have diverged; Bitty aims at the programmable app shell.
- Background / Problem:
  - Need one pass over mainstream and emerging terminals to avoid reinventing wheels or chasing the wrong target.
  - Need to confirm whether web rendering, blocks, workspace, and similar capabilities already have mature implementations.
  - Need to answer the relation of Bitty to WaveTerm and Warp.
- Key conclusions / Decisions:
  - Ecosystem splits five ways: minimal fast, modern native, programmable terminal, terminal workspace, agentic environment.
  - Alacritty as thin reference; Ghostty as native reference; kitty and WezTerm as architecture references.
  - Horizon is close to Bitty Panel thinking and is tracked as an emerging UI subject.
  - Warp is already an agentic development environment; do not copy it head-on, only interoperate with its agent class.
  - WaveTerm is the key product-level reverse-engineering target: blocks map to Panels, wsh maps to IPC.
  - WaveTerm web views are true embedded Chromium, not terminal-cell translation.
  - Bitty differs in lower-level generic Panel, IPC, and plugin abstractions, staying on the native path.
  - Object model fixed as workspace, Panel, task, session; terminal and browser are both Panel implementations.
- Destination: bitty-terminal-docs (ecosystem comparison and Panel choice belong to the terminal repo)
- Open items: None
