# 048 — Coding Agent Quality Factors and Wheel Harness Philosophy

- Status: Captured — `bitty-ai`-owned conclusions distilled as a draft discussion synthesis in `bitty-ai-docs` (`specifications/research/research-distillation-048-049-bitty-ai.md`, accepted through PR bitty-ai#120, merged); captures in other corpora (Wheel/harness, context, tool/ACI, skill, verification owners) not verified — treat remaining sub-conclusions as owner-pending
- Date: 2026-09-18 (archive receipt; the original discussion contains no explicit date)
- One-liner: Agent quality is Model x Harness x Context x Tools x Verification; low signal-to-noise context — not window size — is the root cause, and the harness should keep an already-strong model in the easiest environment to do the right thing.
- Background / Problem:
  - The owner, a heavy user of many coding harnesses, observed that rigid built-in prompts (mandatory skill/MCP inspection before small tasks), bloated low-relevance context, whole-file code reads, brittle tool parameters, and unchecked skill/MCP sprawl degrade task quality more than raw context-window size.
  - The record agrees and generalizes: once base model capability is sufficient, swapping the harness can feel like swapping the model (the SWE-agent ACI finding); verification is called out as the most decisive practice, consistent with published Claude Code and Codex harness retrospectives.
- Key conclusions / Decisions:
  - Quality formula `Q ≈ M x C x A x V x H` (Model, Context, ACI/Tools, Verification, Harness), multiplicative rather than additive: a zero in any factor (no tests, unusable tools, polluted context, rigid prompt) fails the task regardless of model strength.
  - Distinguish context capacity from context utility (Lost-in-the-Middle and Context Rot evidence): optimize Context Efficiency, the share of task-relevant tokens in the active context — a smaller high-signal context beats a larger noisy one.
  - Treat once-useful but now-stale content (repeated logs, full build outputs, resolved error stacks, dead diffs, abandoned plans, duplicated instructions, full subagent transcripts) as context pollution; reduce tool results structurally instead of retaining raw output.
  - Read code as layered cognition (repository tree, symbol index, signatures, references, relevant regions, exact source, whole file only rarely) rather than whole-file dumps; small viewer windows and repo maps outperform bulk context.
  - Design tools for agents rather than exposing internal APIs verbatim (`expose intent, hide plumbing`): minimal strict schemas, clear defaults and descriptions, few overlapping tools; repeated parameter failures are an ACI defect, not a model defect.
  - Keep most capabilities out of the active set: a Capability Registry with relevance-ranked temporary activation (catalog plus search returning a handful of tools) instead of injecting hundreds of schemas; mid-session tool activation must respect prompt-cache stability.
  - Define Skill Hell as discovery collision plus semantic duplication plus instruction conflict plus trigger amplification plus supply-chain risk, and propose a Skill Resolver (overlap detection, dedup, ranking, one-or-two activations, overlap warnings) on top of progressive disclosure, which alone only solves residency, not discovery.
  - Treat skills, MCP servers, plugins, and hooks as code-plus-instruction dependencies with a trust model: provenance tiers plus per-part permissions (read docs freely; execute scripts and touch network only by policy; deny secrets), since skill supply-chain poisoning is an observed real-world attack surface.
  - Keep the core system prompt tiny and principle-based (capabilities, constraints, safety boundaries, environment invariants), shrinking as models grow stronger; give the agent a map, not a manual; make capability use need-driven, never mandatory.
  - Separate durable structured task state (goal, inspected/modified files, decisions, open questions, verification) from disposable conversation; practice continuous context hygiene by information lifecycle (drop ephemeral, pointerize recomputable, structurize state) instead of threshold-triggered summarize-only loops.
  - Make Verification Runtime first-class (action, expected outcome, verification, evidence, state transition) with project-type verifiers inferred from repository markers, so completion is gated by evidence rather than model assertion.
  - Keep Agent, Panel, Process, Workspace, and Session as independent lifecycles joined only by association; treat subagent spawn as an expensive scheduled primitive returning typed results (conclusion, evidence, files, confidence, unresolved) rather than full transcripts.
  - Keep providers behind a unified Model Capability outside the agent architecture; establish evaluation from day one (success, wasted calls, failure rates, context efficiency, skill precision, cost, time) with version-to-version comparison as ground truth for harness changes.
  - Highest principle: at every step the agent sees only the minimum high-quality information needed for the current decision, and every important action gets reliable feedback.
