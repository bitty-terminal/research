# 003 — Terminal Lineage Comparison and Minimal-Infinite Philosophy

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-08-30
- One-liner: Mainstream terminals each cover one stretch; Bitty bets on minimal core plus infinite composition.
- Background / Problem:
  - Need to answer whether Bitty Panels have precedent and what distinguishes Bitty essentially.
  - In 2026 mainstream terminal capabilities are scattered across projects, with no unified reference frame.
  - Bitty needs a one-sentence product philosophy that can spread.
- Key conclusions / Decisions:
  - In 2026 no mainstream terminal covers full terminal emulation, generic Panels, plugin UI runtime, IPC, and workspace together.
  - Zellij is the most direct precedent: plugins and terminal panes are both first-class citizens, with much built-in UI plugin-implemented.
  - kitty and WezTerm match only locally; tmux informs IPC and daemon design; iTerm2 has beside-terminal app thinking.
  - Warp has moved toward the terminal IDE; Bitty should stay differentiated rather than copy it.
  - Closest in spirit is Emacs, but Bitty targets terminals, workspaces, GPU, plugin sandboxing, and an agent-era stack.
  - Ideal state established: minimal core plus infinite extension.
  - Philosophy established: minimal by default, infinitely extensible by design.
  - One Bitty supports both extremes: pure terminal and personal-OS-style environment.
  - Long-term stable abstractions: Panel, Plugin, IPC, Command, Event, Capability, Workspace.
  - Config culture and distributions may evolve, but core boundaries hold.
- Destination: bitty-docs (product positioning and design philosophy belong to the umbrella)
- Open items: None
