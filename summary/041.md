# 041 — IPC Plugin Boundary, Capability Frontends, and Runtime Control

- Status: Captured (plugin direction in bitty-plugins-docs; AI direction distilled in bitty-ai-docs; terminal-side items remain proposals in bitty-terminal-docs)
- Date: 2026-09-16 12:46
- One-liner: The out-of-process IPC boundary is a second plugin surface sharing one capability model across Lua, IPC, and CLI frontends.
- Background / Problem:
  - Lua-in-process plugins cannot serve languages and runtimes that have no Lua bridge, and coarse call granularity makes some integrations inefficient.
  - Giving core knowledge of every out-of-process shape (agents, panels, external tools) would grow the host into a broker of special cases.
  - Plugin-to-plugin communication, crash isolation, and a stable control surface for users and tooling had no agreed boundary.
- Key conclusions / Decisions:
  - Treat IPC as a second plugin boundary beside Lua: the core stays minimal and knows only a small verb set (`agent.spawn/send/cancel`, `panel.attach/output/close`), with the broader surface as candidates.
  - Panel and agent protocol shapes are proposals; panel semantics and ownership stay with the Panel Runtime RFC.
  - A plugin-to-plugin event bus extends the accepted in-host event pipeline; cross-process semantics remain open.
  - One capability model with Lua, IPC, and CLI frontends ("Bitty Capability Protocol"), preserving deny-by-default behavior.
  - Capability tokens and a `[permissions]` TOML sketch are recorded as unaccepted and as diverging from the accepted closed capability grammar.
  - Crash isolation and supervision (restart, disable, log) plus debug surfaces are documented as design directions.
  - A `bittyctl` thin client and `instance -> workspace -> panel` addressing are candidates; the daemon stays deferred by ADR 0008.
  - A candidate three-layer model is reconciled with "runtime flat, semantics layered" from 040.
- Destination: bitty-plugins-docs (`specifications/plugin-ipc-boundary.md`), bitty-ai-docs
- Open items: Seven research open items recorded in `plugin-ipc-boundary.md`; accepted IPC scope is limited to instance discovery and selection, and the `bittyctl` method surface is not yet accepted.
