# 014 — Panorama Calibration and Core Ontology Freeze Proposal

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-09-13 17:57
- One-liner: Affirm the panorama direction, correct vision concepts intruding into lower layers, and freeze the core ontology and invariants first.
- Background / Problem:
  - The panorama study established a skeleton of small core, mechanism-policy separation, and panels-are-not-terminals, but some product metaphors began intruding into the underlying model.
  - Session restore, panels versus execution, agent loops, and context budgets carry long-term architectural risk.
  - The core abstractions need one calibration pass before more features are added.
- Key conclusions / Decisions:
  - Split session restore into UI state restore versus execution continuity; layout and scrollback can be restored, while live processes and descriptors cannot be reliably serialized and need a daemon plus remount-separation design.
  - Panels are views, not execution itself, and workstations remain only a product metaphor; separate execution context from presentation to support one-to-many, many-to-one, headless, and remote execution.
  - Lua owns only orchestration policy; cancellation, timeouts, accounting, permissions, concurrency, backpressure, retries, auditing, and state machines belong to host execution semantics.
  - Drop fixed byte-based context budgets in favor of token, byte, priority, and detail requests that return summaries plus expandable context artifacts.
  - Keep terminal semantic state on CPU and persistent storage, keep only visible render assets in graphics caches, and expose semantic interfaces for querying commands, fetching output, fetching summaries, and fetching errors.
  - Evolve cross-plugin calls from small-value deep copy toward small-value copy, numbered large immutable resources, bounded streaming channels, and privileged opaque capability handles.
  - Treat selector, statusline, and context as conventions on the service bus only, leaving room for future command, completion, tool, panel, and action providers.
  - Split the core-plugin boundary again by mechanism versus policy, with primitives in the core and interaction plus policy in plugins; upper rich-text layers use only high-level components, never raw scene nodes directly.
  - Build a graded threat model from core to external tools, stating which file, network, process, clipboard, credential, input-output, communication, and graphics capabilities each layer may request.
  - Redefine the product as a programmable workspace runtime plus a terminal-native execution environment; restate multi-agent work technically as a spatially anchored runtime, lifting context from session memory to environment state.
  - Reorder the roadmap to fix architectural contracts before building terminal, programming runtime, workspace, rich application platform, AI, and multi-agent layers; first write the core ontology document freezing ownership and lifecycle for about ten top-level concepts.
