# 064 摘要：capability 插件架构总纲（trimmed mirror of origin/064.md）

两条核心原则（boxed）：
$$\boxed{Plugins\ share\ infrastructure,\ not\ duplicate\ infrastructure}$$
$$\boxed{Plugins\ request\ capabilities,\ not\ own\ system\ privileges}$$

## 1. 原则：插件不携带系统能力，只声明需要什么
`bitty-network` 定位从"依赖复用"升级为原则：插件不能自带一套系统能力，
由 Bitty 上游统一提供、调度、授权。否则几年后生态熵增（每个插件自带
runtime/依赖/worker/cache）。

## 2. 三层价值（network 为例）
dependency reuse < 无"自己联网"能力 < 统一 runtime+policy。
Lua 禁：socket.connect、ffi.load(libcurl)、os.execute(curl) 等绕过
permission system 的路径；只允许 `bitty.require("network")` →
Capability Manager → bitty-network → Internet。

## 3. Piccolo/Phodopus 选择是同一件事
Piccolo 本身不自动给 sandbox；真正边界 = Lua VM + 暴露的 Host
Functions + Capability System + Resource Limits。不提供 raw
socket/arbitrary FFI/arbitrary spawn/unrestricted fs/raw secrets，
恶意 Lua 也无路径出去。接近 capability-based security：
安装插件 ≠ 获得用户全部权限。

## 4. bitty-network 身份：Network Capability Provider
provides: network.http/websocket/tcp/udp/quic/listen/discovery。
manifest：`[capabilities] network=["http"]` + `[network]
allow=["api.github.com"]`。漂亮区分：client≠listen、HTTP≠raw
TCP、某 host≠任意 host。

## 5. 以后的 capability 会越来越多
bitty-network/process/fs/secrets/media/notify/remote；分属 Core
或 Optional Extension。Lua 不直接碰 OS：Plugin → Capability
API → Core → OS。目标：比 VS Code 插件资源模型控制得更好——
关键不是 Lua 轻，而是架构上避免"插件=新 runtime+依赖堆+worker+cache"。

## 6. 共享（Share, 不 Duplicate）
event loop（Bitty Async Runtime 统一 task）、network 连接池
（5 个 GitHub 插件共享 api.github.com HTTP/2 池）、timer
（bitty.timer.every，单 scheduler）、UI renderer（插件交
UI description/state，共享 wgpu 上下文/font cache）。

## 7. Resource Quota（v1 架构就该有）
每 Plugin Instance budget：memory/CPU time/tasks/processes/
connections/bandwidth/timers/storage；manifest `[limits]` +
默认等级 tiny/normal/heavy/system（可不手写，可自动统计）。

## 8. Plugin Manager introspection
按插件资源视图（Memory/CPU/Tasks/Network/Storage）+
Suspend/Restart/Disable/Kill/Inspect。解决"卡了不知是谁"。

## 9. Lazy Loading：installed ≠ loaded ≠ active
触发器：git 仓库检出、面板打开、/wheel 命令、workspace 启用。
目标 Installed:100 / Loaded:12 / Active:4。

## 10. Headless suspend
无事做时 Active→waiting→Suspended，timer/network 事件唤醒；
Phodopus 可围绕 suspension model 优化，与 Headless Panel 统一。

## 落地
Shared Services + Capability System + Quotas + Lazy Loading +
Lifecycle + Dependency Reuse + Introspection = 控制 Extension
Ecosystem Entropy。API 面向 capability 而非 crate：Rust 侧是
crate，插件侧只知道 network capability——以后换
reqwest/hyper、rustls、Tokio 甚至迁 networkd 都不破坏插件。
