# 009 — Composable Layers and Window Semantics

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-09-09
- One-liner: Isolate large-scale complexity with layers; identity defines the composable workspace.
- Background / Problem:
  - Stacking workspace, plugins, IPC, and rich UI over a terminal core inevitably inflates complexity.
  - Need to answer whether complexity is correctly layered, not compare raw line counts.
  - The foundation is now complete; must decide whether to harden first or keep building ecosystem upward.
- Key conclusions / Decisions:
  - Long-term five layers: user plugins, composition layer, workspace UI runtime, terminal runtime, platform layer; IPC cuts across under capability constraints.
  - Philosophy follows a microkernel style: small trusted mechanisms, replaceable policies, message and service composition.
  - Window management favors dynamic composition over fixed layouts, abstracting surface, container, layout, workspace, focus, and navigation.
  - IPC is a necessity to prevent plugins from wiring directly into internals.
  - AI is never a special Core citizen; Core knows only events, commands, services, permissions, panels, processes, sessions, and IPC.
  - Rust owns mechanisms, Lua owns policy; AI repo and terminal agent repo are deliberately separated.
  - Services are promoted to first-class citizens; plugins compose via service semantics, for example AI plus code diff composes a review plugin.
  - Terminal agent repo and AI repo are deliberately separated; the AI repo splits by runtime, context, tools, and execution conceptual boundaries.
  - Identity fixed as composable terminal workspace, not AI terminal or GPU terminal.
  - Cadence pauses expansion to verify terminal, workspace, plugin lifecycle, IPC, security, performance, and compat before growing the ecosystem.
  - Window semantics: tiling by default, floating for temporary, overlay for transient, stash for recall; default Alt as Mod but no unregistered key passthrough to the terminal.
  - Key dispatch fixes priority, supporting Mod and Leader coexistence; help panel doubles as key hints.
- Destination: bitty-terminal-docs, bitty-plugins-docs, bitty-ai-docs (layering and windows to terminal and plugin repos, AI split to AI repo)
- Open items:
  - Full Rust versus Lua interface openness still needs convergence.
  - Panel rules and mode attribute details are undecided.
