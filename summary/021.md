# 021 — Agent Organization Runtime and Shared Workspace Infrastructure

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-09-14 17:58
- One-liner: Agents share processes and toolchains, with organized collaboration and compilable context.
- Background / Problem:
  - Each subagent starting its own language service balloons memory and leaves residual processes piling into swap after exit.
  - A single commander with multiple workers cannot support large long-running tasks, causing context explosion and unclear responsibilities.
  - Chat history keeps appending full text and raw command output, wasting tokens heavily.
  - Agent and panel lifecycles are tightly coupled, so ending one side often harms the other.
- Key conclusions / Decisions:
  - Agents are logical entities existing as async tasks; use separate processes only when isolation is required.
  - Language services, diagnostics, builds, and indexes are owned shared by the workspace and reused per workspace view; agents are only consumers.
  - Agents never call language protocols directly; expose only semantic code-intelligence interfaces with swappable backends.
  - CLI checks are deduplicated and merged per workspace version, executed once with fanned-out results; builds share one queued, deduplicated, rate-limited, cached pipeline.
  - Workspace services use reference counting plus idle-timeout reclamation, LRU eviction under memory pressure, and OS groups for resource limits.
  - Share language services within one workspace view; distinguish different worktrees by repository plus worktree plus configuration.
  - Large tasks use a four-level org chart of Mission, organization, team, and agent, with a span-of-control cap; leaders may create sub-teams within their authority.
  - Separate managers from executors; superiors see execution summaries by default, structured meetings replace free chat, and task budgets prevent unbounded spawning.
  - Context is layered into identity, mission, workspace, task, working set, and memory; store references not full text, compiled per role and budget.
  - Command records are tiered into summary, structured result, and raw output; file reads expand progressively from outline to symbol to lines.
  - Agents communicate over a structured message bus so most state events need no model involvement; three tiers of local channel, workspace IPC, and global IPC.
  - Agents and panels form a many-to-many lease; presentation state is separated from lifecycle, and context migrates with the agent.
  - Panels share one model with headed and headless presentations only; lifecycle is create, active, idle, archived, destroyed.
  - Entering a user panel has observe, assist, and take-over levels, attaching in background without stealing focus by default; the official console unifies org, task, panel, and resource views.
  - Establish invariants: agents own neither language services nor panels, context belongs to the runtime, communication prefers references and structured events, and raw output never enters the model by default.
