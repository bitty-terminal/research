# 034 — Fix the Release Pipeline Vertically

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-09-15 13:53
- One-liner: Stops adding distribution formats and fixes the existing packaging, install, and run chain.
- Background / Problem:
  - Mainstream package formats and channels are already covered; horizontal expansion carries high maintenance cost.
  - Review found missing architecture-matrix entries, binaries mismatched with target systems, and nonstandard package suffixes.
  - Placeholder terminal-info files and missing desktop metadata hurt formal release quality.
- Key conclusions / Decisions:
  - Converge the support matrix on mainstream desktop architectures; defer niche architectures and emerging packaging systems.
  - Restore the already-written but unenabled desktop ARM build-matrix entries.
  - Alpine packages switch to native or genuinely target-compatible builds instead of repackaging generic binaries.
  - Fix the Arch package suffix to the standard format, split runtime dependencies per distribution, and trust linker output.
  - Every package type must pass install, version, self-check, and smoke-run verification in a clean container.
  - Fix the placeholder terminal-info definition by making it real or skipping installation; add app metadata and pin the app ID.
  - Normalize compressed distribution formats; prefer a generic image on desktop and a portable archive on Windows first.
- Destination: bitty-terminal-docs
- Open items: None
