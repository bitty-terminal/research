# 027 — Mainstream Prompt Sizes and Target Budget

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-09-15 00:10
- One-liner: Core around a thousand words, capabilities loaded on demand.
- Background / Problem:
  - Core prompt and first-request totals are often conflated, and tokenizers differ across models so counts are not directly comparable.
  - Bloated skill and tool catalogs can make first-turn cost far exceed the core itself.
  - The own runtime needs a defensible budget target.
- Key conclusions / Decisions:
  - Minimalist cores run hundreds of words, open multi-template ones two to three thousand, model-specific ones roughly two and a half to four and a half thousand, heavy combined cores thousands with assembled totals over ten thousand.
  - Clarify the metric: core prompt does not equal assembled first-request size.
  - Set the own core target around a thousand words, aiming for two and a half to five thousand words in the first turn after assembly.
  - Core teaches only runtime semantics and invariants; interfaces ride tool schemas and flows ride skills.
  - Keep detailed panel docs out of core, loading via self-description interfaces or skills on demand.
  - Core contracts stay immutable within a version and placed first, naturally favoring prefix cache.
