# 004 — Hermes Inspiration and Agent Platform Positioning

- Status: Captured (conclusions recorded in *-docs)
- Date: 2026-08-30
- One-liner: Learn session hosting from Warp, long-term growth runtime from Hermes.
- Background / Problem:
  - Copying only Warp would make Bitty another heavy coding agent.
  - Long-lived agents need skill discovery, memory, context, delegation, and multi-environment execution protocols.
  - Mainstream harnesses have converged; Bitty must add runtime protocols that can evolve long-term.
- Key conclusions / Decisions:
  - Positioning converged to agent runtime foundation, not terminal plus chat.
  - From Warp borrow sessions, harness, rich UI, PTY ownership, and human takeover; from Hermes borrow skills, memory, context, and multi-environment.
  - Skills use progressive disclosure with a unified SkillProvider to avoid stuffing prompts.
  - Memory separates hot memory from cold history; writes go through proposal and approval.
  - Context store is fully separated from model active context, supporting snapshot, compaction, restore, and budgeting.
  - Child agent contexts are isolated; child permissions can only shrink from the parent.
  - Execution targets cover local, SSH, containers, and remote sandboxes.
  - Tool bus supports MCP, native, and RPC; MCP is only one of the tool buses.
  - Agent file edits use transactional and reversible design; verification is a first-class primitive; sandboxes are tiered by level.
  - Terminal output uses tiered disclosure and structured references; full text is not sent to models by default.
  - Terminal event stream replaces brute-force screen scraping; memory settles in four tiers; growth means distilling experience, not piling up context.
  - Five new RFC categories added: harness, knowledge and memory, context lifecycle, delegation, execution targets.
  - Self-growth provides only primitives and stays out of Core; observability, replay, and evaluation are designed in from the first release.
- Destination: bitty-ai-docs (agent platform and context protocols belong to the AI repo)
- Open items:
  - Interfaces for the five RFC categories still need drafting.
  - Security approval details for self-growth and memory writes are undecided.
